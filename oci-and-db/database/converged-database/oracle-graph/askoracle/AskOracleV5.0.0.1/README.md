# Visualization extensions for Ask Oracle

If you already have **Ask Oracle Release Version: 5.0.0.1** installed, you can add the functionality provided in this repository. If not, first download Ask Oracle from the [official Oracle repository](https://github.com/oracle-devrel/oracle-autonomous-database-samples/tree/main/apex/Ask-Oracle-Select-AI-Chatbot/V%205.0.0.1) and follow its installation instructions. You can find the base application's prerequisites and setup details there.

Then follow the instructions below to add these extensions to your own application.

**This is a component package, not a complete Ask Oracle application or a one-click installer.** It does not include your database data, AI credentials, or AI profile configuration. It is intended for an existing Ask Oracle 5.0.0.1 installation; other releases have not been verified.

> Start in a development copy of your application and back up the components you will replace. The included page export was generated by **APEX 26.1.4**. Ask Oracle's release number and APEX's version number are different. Compatibility with the base Ask Oracle release does not guarantee that this page export can be imported into an older APEX instance or an unrelated application.

## 1. What can you add?

| Component | What it adds |
| --- | --- |
| Graph Visualization plugin and graph page | A graph viewer for generated property-graph SQL results. |
| Cytoscape and D3 integrations | Alternative graph renderers for results containing recognized graph identity columns. |
| MapLibre integration | A map for returned point, line, and polygon GeoJSON, including district boundaries. |
| Map interactions | A selectable attributes table, yellow feature/row selection, Select All, Clear Selection, right-click sorting, and Shift+drag selection. |
| Drawing | Draw points, lines, polygons, and rectangles; select drawings and inspect their attributes. |
| Browser storage | Named drawing sets, optional feature names/attributes, local loading, deletion, and Undo/Redo history. |
| Spatial analysis | Intersects, Within, Contains, Touches, Overlaps, and Disjoint between drawings and complete loaded GeoJSON sources. |
| Map PDF export | Export the open map, current map appearance, visible chart, and mapped attributes without dumping raw geometry into the table. |

These components display the results returned by the application. They do not make an LLM generate correct SQL, create property graphs, or guarantee that all database rows have been fetched.

## 3. Before installing

1. Confirm that your existing Ask Oracle 5.0.0.1 app can run an ordinary NL2SQL question successfully.
2. Back up the app locally and record its current JavaScript/CSS URLs, page-load code, processes, and plugin versions. You do not need to publish that backup.
3. Identify the app's parsing schema and actual chat-page number. Several supplied runtime references use `P1_*` items; they are not automatically portable to differently numbered pages.
4. Choose the features you need. Map-only installation does not require the graph plugin, graph page, or graph SQL function. Browser drawing storage does not require Oracle tables.
5. For graph functionality, ensure your database supports the SQL property-graph queries you use and your schema can access the graph and underlying data. For map functionality, return valid GeoJSON.
6. Use a modern browser with WebGL; browser drawing storage also needs IndexedDB. Browser policy or private browsing can restrict persistence.
7. Review external-library and tile-service access with your organization's CSP/network policy. Do not disable security controls just to make a dependency load.

### Database and callback dependencies to verify

The supplied function reads `USER_CLOUD_AI_CONVERSATION_PROMPTS` and `ADB_CHAT_PROMPTS`. The supplied `GET_SQL_RESULTS` also reads `CONVERSATION_TIME`. These objects are not created by this component package. Check their existence and required columns in your base installation.

The broad application runtime calls additional processes, including `EXECUTE_PROMPT`, `GET_RESPONSE`, `GET_PROMPT_HISTORY`, `GET_LATEST_CONV_ROW`, `DELETE_PROMPT`, `GET_AGENT_THOUGHTS`, `GET_AGENT_AUTO_VISUAL`, `CREATE_NL2SQL_SHARE_URL`, `SET_CONVERSATION_STYLE`, and `SETTINGS_*` callbacks. This repository does not separately export all of those processes. Keep the base app's working processes and compare any customized runtime before adopting it.

**Security:** the supplied function uses definer rights, and both query paths work with saved SQL. Text/keyword checks are not a SQL security sandbox. Before exposing the callbacks to users, verify authentication, authorization, prompt/conversation ownership, and least-privilege database access. The supplied bodies do not by themselves establish that the requested prompt belongs to the current APEX user. Never insert arbitrary untrusted SQL into the saved-response tables for these callbacks to execute.

## 4. Install the graph components, if wanted

### Step 1 — Install the database function

Open `function/ask_oracle_graph_sql.sql`, review it, then compile it using SQL Workshop SQL Scripts or your SQL client while connected to the app's parsing schema. Check that `ASK_ORACLE_GRAPH_SQL` is valid and has no compilation errors.

This function retrieves a saved response by prompt ID. It removes supported SQL fences/prefixes, checks for a SELECT/WITH graph query, validates it, and returns the SQL. It does **not** repair incorrect joins, generate graph SQL, or adapt every possible query into the plugin's required columns.

### Step 2 — Import the plugin

Use **App Builder → Import**, choose `plugin/region_type_plugin_graphviz.sql`, select the Plug-in file type, and install it into your target application. Review any existing plugin with the same internal name (`GRAPHVIZ`) before replacing it.

The plugin's `#PLUGIN_FILES#` assets belong to the plugin. Do not substitute `#APP_FILES#` for those references.

### Step 3 — Review and install/recreate the graph page

> **Do not blindly execute `f909923_page_14.sql`.** It contains source workspace/application identifiers and a call that removes page 14 before recreating it. Do not overwrite an existing page 14. A single-page export can also reference shared-component IDs that differ in another application.

Use a compatible APEX environment and verify the target application and dependencies before any import. If the page cannot safely be imported, use it as a configuration reference and recreate the page manually. Refer to [Oracle's page-export restrictions](https://docs.oracle.com/en/database/oracle/apex/26.1/htmdb/exporting-an-application-page.html).

The important exported settings are:

| Setting | Supplied value |
| --- | --- |
| Page number / name | `14` / `Graph` |
| Hidden prompt item | `P14_PROMPT_ID` |
| Layout item | `P14_GRAPH_LAYOUT` |
| Region type | Graph Visualization (`GRAPHVIZ`) |
| Region Static ID | `graph-view` |
| Region Name | `graph` |
| Source type | PL/SQL function body returning SQL |
| Region source | `RETURN ask_oracle_graph_sql(:P14_PROMPT_ID);` |
| Exported region columns | `V_ID`, `E_ID`, `P_ID` |

The export also contains page-load JavaScript and a layout-change dynamic action. Preserve or adapt those when recreating the page; creating only the region is not equivalent. Check the region identifiers used by the JavaScript against your target page. If you change the page number, rename the items and update all matching references, including `GET_GRAPH_URL`.

### Step 4 — Configure the two callbacks

Open **Shared Components → Application Processes**. For an on-demand callback, select the process point **On Demand: Run this application process when requested by a page process** (label may vary by APEX version).

- **GET_GRAPH_URL:** use the body from `Application_Process/GET_GRAPH_URL.txt`. It accepts a prompt ID through `apex_application.g_x01` and returns a JSON object with `url`. The supplied code targets page `14` and item `P14_PROMPT_ID`.
- **GET_SQL_RESULTS:** locate the existing process first, including page-level Ajax Callbacks if necessary. Compare and back up its body before using `Application_Process/GET_SQL_RESULTS.txt`. Do not create a second conflicting callback with the same name.

The supplied `GET_SQL_RESULTS` returns `id`, `totalRowCount`, `profile_name`, `conversation_time`, `sql`, and `results`. It fetches **at most 50 rows** using `p_max_rows => 50`. A larger total count does not mean all rows are available for a visualization.

### Graph result columns

The graph plugin and the Cy/D3 scripts do not necessarily use the same column contract. The exported plugin region declares `V_ID`, `E_ID`, and `P_ID`. The Cy/D3 integrations recognize names such as `GRAPH_SOURCE_ID`, `GRAPH_TARGET_ID`, and `GRAPH_EDGE_ID`; some paths also recognize `GRAPH_VERTEX_ID`.

For an edge, its source/target identities must describe that edge's actual endpoints. Do not return customer IDs as endpoints for a transfer edge that connects accounts. Ordinary business columns alone are not always enough for these renderers. Node-only and arbitrary-alias results are not supported uniformly; D3's supplied property-row conversion requires source and target graph columns.

## 6. Use the map and drawings

### Return geometry with query results

The map requires valid GeoJSON in WGS84 longitude/latitude order. Recognized column names include `GEOJSON`, `GEOMETRY`, `GEOM`, and names ending in `_GEOJSON`, but their values must actually contain GeoJSON. A raw `SDO_GEOMETRY` object or WKT string is not sufficient.

For example, when `GEOM` already uses the correct coordinate reference system:

```sql
SELECT district,
       population,
       SDO_UTIL.TO_GEOJSON(geom) AS geojson
FROM your_district_table;
```

Replace the example table/columns with your schema. Conversion to GeoJSON alone must not be assumed to transform a different coordinate reference system. If you want users to ask only “Show districts and population,” the profile/backend must still arrange for geometry to be returned. The JavaScript does not rewrite generated SQL to add it. Show SQL may legitimately display the geometry expression even when the visible attributes table hides that column.

Open **Show Map**. Click a district or its attributes row to toggle yellow selection. Use **Select All**, **Clear Selection**, or **Shift+drag** for visible intersecting-feature selection. Right-click an attributes heading/cell for ascending or descending sorting. Selection operates on mapped returned features, not every row in the database.

### Draw and inspect

Use the **Drawing** menu:

- **Point:** click to place a point.
- **Line / Polygon:** click vertices, then choose **Finish** or press Enter. Escape cancels the unfinished drawing.
- **Rectangle:** drag without Shift.
- **Select drawing:** click a drawn feature to highlight it, without automatically opening a popup.
- **Right-click a drawing:** Select feature, Deselect feature, or Show attributes.
- **Delete drawing:** remove a clicked drawing. **Clear drawings** removes current annotations from view, not the database result layer.

### Save locally

Use **Save drawings**, provide a set name, and choose whether to add optional feature names/custom attributes. Geometry-only saving is allowed. **Load drawings** restores a selected set and its attributes; it replaces current annotations, not districts.

Completed drawing changes are autosaved with bounded Undo/Redo history (up to 100 steps). This is not an immutable backup. When a saved current state is empty, loading can recover the most recent nonempty retained history state; recovery is not guaranteed after history is discarded.

**Delete saved set** removes one named set. **Clear all saved drawings** removes sets and history in the current app/user scope after confirmation. These actions are separate from clearing the map view. Visible drawings remain after saved-storage deletion, and autosave is paused until an explicit Save or Load.

Storage uses IndexedDB in the current browser/site, scoped by app/user information when available. It does not synchronize to Oracle or other devices. Clearing browser site data, browser eviction, private-mode restrictions, or changing origins can make drawings unavailable. It is not encrypted secure storage or a backup service; avoid sensitive attributes on shared browsers.

## 7. Spatial analysis

Click the **Analysis** label beside Drawing to open the dropdown. Choose a relationship, then choose **Layer A**, **Layer B**, and all or individual features. Click **Run analysis**.

Example: to find districts crossed by a drawn line, choose **Intersects**, A = Drawings / your line, B = Map results / districts / All features.

Matching pairs appear in a table. Cyan highlights are independent of yellow map selections. **Highlight pair**, **Highlight all results**, and **Clear analysis** affect analysis highlights only. Source changes invalidate the result snapshot.

| Relationship | Meaning, in the A → B direction |
| --- | --- |
| Intersects | At least one shared point, including boundaries. |
| Within | A is within B and their interiors intersect; a point on a polygon boundary is not within it. |
| Contains | The reverse of Within. |
| Touches | Boundaries meet without intersecting interiors; two points do not touch in this topological sense. |
| Overlaps | Same-dimensional features partly overlap without one containing the other. Crossing lines at a single point do not overlap. |
| Disjoint | The listed A–B pair has no shared point. This does not mean A is disjoint from every feature in B. |

Analysis limitations:

- Complete inline GeoJSON sources only; URL-only GeoJSON sources, raster tiles, and vector basemap tiles are excluded.
- Completed drawings only; live previews are excluded. Same-source self-pairs are excluded.
- XY planar topology, no snapping tolerance; elevation is ignored. Invalid/unsupported geometry and longitude spans over 180 degrees are rejected.
- Maximum 25,000 candidate pairs, 1,000 displayed matching pairs, and a 150,000-coordinate preparation budget. Partial results are explicitly identified.
- It does not perform distance, area, buffer, routing, or database-wide analysis.

The module loads **JSTS 2.12.1** from jsDelivr on demand. Feature coordinates are processed locally, not sent to JSTS's host. For an approved local deployment, preload a compatible JSTS browser build or set this before the analysis script loads:

```js
window.askOracleMapAnalysisConfig = {
  libraryUrl: "#APP_FILES#jsts.min.js"
};
```

Put this in an APEX setting where substitution strings are expanded. Literal `#APP_FILES#` strings inside an uploaded static JavaScript file are not automatically substituted. A separately hosted JSTS file is not included in this ZIP.

## 8. PDF and external services

Open the populated map before exporting a map PDF. Wait for basemap tiles to finish loading. Show a chart first if you want that visible chart included. The PDF module uses the app's existing jsPDF loader and captures the current viewport, including map selections and drawings, followed by mapped attributes. It is not a database-wide export. Analysis result tables are not separately exported by this module.

The default basemap uses OpenFreeMap. Its tile/style services receive normal network requests, including requested map areas and client network information. Keep attribution visible. To use an approved map service, set `window.askOracleMapConfig.style` before loading the main map integration; setting `style: null` provides a blank background.

External assets can include Cytoscape, D3, JSTS, chart/PDF libraries, map styles, glyphs, sprites, and tiles. Self-host approved dependencies where required and configure CSP for the resources actually used. Browser-only geometry storage/analysis does not mean the whole application is offline: Ask Oracle still uses its configured database/AI services.

## 9. Test before sharing with users

1. Verify normal Ask Oracle questions still work and are submitted only once.
2. Run a known-good property-graph query. Check the plugin view and, where the column contract matches, Cy/D3 views.
3. Return one polygon with readable attributes. Check Show Map and absence of raw geometry in the selectable attributes table.
4. Verify row/map selection, sorting, Select All, Clear Selection, and Shift+drag.
5. Draw a line; Finish; name/save it; clear the view; Load it. Verify its name and attributes.
6. Refresh the page, open the map again, and load the saved set.
7. Run Intersects between the line and districts. Check the listed pairs and cyan highlights.
8. Export a map PDF with a visible chart and inspect the actual downloaded PDF.
9. Test permissions with another authorized user: no access to another user's saved prompts through callback IDs.
10. Scroll the map page up/down and verify rendering remains stable in your target browser.

## 10. Troubleshooting and known limitations

| Symptom | Check |
| --- | --- |
| No map / no usable geometry | Result payload, GeoJSON column and coordinate system; raw Oracle geometry is not browser GeoJSON. |
| Drawing storage or Analysis missing | Correct filenames, module load order, JavaScript errors, and whether the drawing toolbar initialized. |
| JSTS cannot load | Network/CSP or local library URL. Do not weaken security settings indiscriminately. |
| Graph view has no rows | Generated SQL, relationship directions, selected profile, actual data, and graph identity columns. The renderer cannot invent missing results. |
| “No graph columns were found” | Renderer-specific aliases/contracts; ordinary IDs or unsupported node-only results may not be recognized. |
| More total rows than map/table rows | `GET_SQL_RESULTS` fetches 50 rows, and geometry validation/limits can reduce mapped features further. |
| Duplicate controls or requests | Duplicate runtime scripts, `.js` plus `.min.js`, or duplicated page-load initialization. |
| `chartjs-plugin-funnel` reads undefined `elements` | Review the chart plugin/Chart.js combination separately. This message alone does not diagnose a map-rendering issue. |
| Map becomes white during page scrolling | This has been observed in the source app and remains unresolved. Matching canvas/container sizes and a valid WebGL context did not establish the cause. Do not claim this package fixes it. |
| Long generated SQL fails | The supplied result callback uses a 4,000-character SQL variable; the graph function's validation parses a substring of up to 32,767 characters. Arbitrarily long queries are not guaranteed. |
| Import fails or references the wrong components | APEX version, source component IDs, target page conflicts, plugin dependencies, and region/item names. Use manual recreation where necessary. |

Local syntax, topology, and simulated integration checks were performed for the analysis module. A complete clean installation of this sharing package into a separate Ask Oracle 5.0.0.1 app has **not** been verified. Do not interpret source-app observations as certification for every deployment.
