# Setup

1. Resolve the project repository internally as `multicloud-control-plane/<repository>` before every operation. Read its `origin` only to confirm it is the expected handed-off private `nonprod-<project>` or `prod-<project>` repository whose default branch is `main`; never infer an organization from it. The matching `environments/<environment>/environment_information.md` supplies the approved handoff references.
2. Use `multicloud-control-plane/gitops-templates` at `main`. Choose `resources-catalog` for infrastructure or `operations-catalog` for OCI lifecycle work. The catalog is the only source for supported fields and destination paths. Platform CI and the selected orchestrator are the only validation authorities; do not recreate their checks locally.
3. A template-only `.github/CODEOWNERS.template` is valid; Project Team owns its active CODEOWNERS configuration.
4. For OCI ADB, render `__ADB_ADMIN_PASSWORD_SECRET_OCID__` into `admin_password_secret_id` using an existing OCI Vault secret OCID. Ask the requester for a missing OCID, never a password. Each database has its own secret, scoped to the selected project/environment and located in the OCI deployment region. Do not substitute a logical dependency key: the approved Orchestrator v2.3.0 workflow does not pass `secrets_dependency` to ADB. Project Team manages the value and current version in Vault; Cloud Operations configures the runner's scoped read permissions. The native module reads `CURRENT` and validates the published password policy: 12 to 30 characters, uppercase, lowercase and digit, no double quote and no `admin` substring in any casing. State this policy as a prerequisite without reading or checking the value.
5. For fields without native support, such as Azure ADB passwords, render an environment-qualified, resource-scoped runtime token. For database key `ordersadb` in `dev`, use `__DEV_ORDERSADB_ADMIN_PASSWORD__`. Its binding name is `DEV_ORDERSADB_ADMIN_PASSWORD`. Derive names by uppercasing the database mapping key, replacing runs of non-alphanumeric characters with one underscore, and trimming leading/trailing underscores. Cloud Operations registers the exact repository and cloud/environment/region binding to a Vault secret OCID and OCI region outside Git. Project Team creates or updates that value in its approved Vault scope. A GitHub secret bundle is never a prerequisite or fallback. The agent does not read the binding file, call OCI, or verify its existence: state the required binding and ask Cloud Operations to confirm readiness through the approved process. Google ADB retains its provider-native `properties.secret_id` reference.
6. Every secret-bearing preview lists native references per database and/or required runtime binding names and their selected repository/cloud/environment/region. State that the references, current versions, and scoped runner access must already be prepared through the approved process. Do not provide a JSON object of password values, request values, or claim to have validated contents or IAM. Publishing a new current version is consumed by the next reviewed plan/apply; it does not itself deploy a password change. Diagnose missing or denied references from workflow evidence only.
