# Working notes for coding agents

- Python side uses `uv` (`uv sync`, `uv run …`). Web side is Next.js 16 in `web/`; read `web/AGENTS.md` (generated by `next dev`) before touching App Router code.
- The model is an imported model on a dedicated OCI endpoint. Only the OpenAI-compatible Chat Completions route works for it; the Responses API returns 400 for imported models. Do not try to move the agent to Responses, MCP-hosted tools or hosted apps.
- Use function calling, not `response_format: json_schema`. Strict guided decoding has stalled on Qwen endpoints before.
- Reasoning: `reasoning_effort` in `none / low / medium / xhigh`. `none` is still not always honoured; hidden reasoning tokens are billed as completion tokens.
- All patient data is fictional and lives in `data/patients.json` (seed) and `data/labsense.db` (runtime, gitignored). Never add real patient data.
- Keep OCI credentials server-side. Both services bind to loopback. `.env` is gitignored.
- Validity windows in `data/catalog.json` are illustrative; keep the on-screen disclaimer.
- Lint rules are strict (React compiler rules): no ref reads during render, no synchronous setState inside effects, no `let` reassignment in render. Run `npm run lint` before claiming a change works.
